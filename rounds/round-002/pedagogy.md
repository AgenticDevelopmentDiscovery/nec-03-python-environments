# Pedagogical Readiness — Round 2

**Recommendation:** needs revision
The `venv`/`uv` mechanics are genuinely teachable as written, but the section's own capstone demo and the conclusion's promised payoff are not actually on the page.

**Audience read against:** Graduate students in the agentic-development course who already write and run Python scripts and have installed packages with `pip`, but have never created a virtual environment, generated a lockfile, or had to reproduce a result on a different machine.

## Strengths
- `sections/01-context.prose.md` and `sections/02-motivation.prose.md` are pitched exactly at the declared gap: they define what the audience hasn't seen (venv, lockfile, spec) without re-explaining what it already has (scripts, `pip install`), and the isolation-before-after and drift-chain figures carry a relationship the prose would otherwise have to spell out in one dense sentence.
- The `venv` and `uv` walkthroughs in `sections/03-content.prose.md` give the reader an actual, ordered command sequence for both tools (`python -m venv .venv` → activate → install → `pip freeze`; `uv venv` → `uv pip install` → `uv lock`), with each figure answering "how do I update it" directly — the two tools read as genuinely parallel paths, not one treated as a footnote of the other.
- Pitfalls closes `03-content` with three concrete, nameable failure modes (partial pinning, an uncommitted lockfile, locking without seeding) that map straight onto the "recognize drift" capability `topic.md` promises the reader will leave with.

## Weaknesses
- `sections/03-content.prose.md` § Demo: prove it with the bike-sharing example — this is the section's proof that a lockfile actually reproduces the environment, and on the page it is three abstract bullets: no path, no command, no expected output. The only concrete recipe for this demo anywhere in the repo, `bike-sharing-offline-trial/demo/README.md`, is explicitly marked "Not part of the regression assignment" and written as a presenter script ("**Say:** ...") for an instructor to run live in front of the class — it is not linked from the prose and is not written for the declared reader to run solo. A student working through this section cannot do the one thing it is built around; they can only be told it happened.
- `sections/04-conclusion.prose.md` § What you can do now — both `topic.md`'s Shape section and this section's own spine (`04-conclusion.concepts.md`, Decisions) state that C1's repo artifact, C2's leaderboard, and C4's generate→evaluate→select loop are folded into "What you can do now" as concrete downstream use. None of that is in the shipped prose; the section states the capability and stops. This is the spine recording an integration as done while the prose never received it — the exact promise-vs-delivery gap this seat is briefed to catch, and it leaves the tutorial's closing section short of its own stated proposal.
- `sections/03-content.prose.md` — every executable command in the section (the full `venv` and `uv` sequences) lives only inside an SVG figure; none appears in prose or a fenced code block. A reader following along in the document or site has nothing to copy — only a diagram to transcribe by hand.
